# career-site-home 시안 (4라운드, 홈 화면)

**선택: M 명함 (2026-11-14, 사용자 선택)**. "M 레이아웃이 좋다." 홈 화면은 M으로 간다. 이력서 페이지 시안과 홈에 넣을 프로젝트는 아직 정하는 중이다. 정해지기 전에는 운영 코드(`src/`)를 고치지 않는다.

## 요청

3라운드([career-site-simple](../career-site-simple/README.md))를 본 사용자가 "내 사이트로도 사용해야 함"이라고 했다. (2026-11-13)

사용자 확인 사항 (2026-11-14)

- 이력서 말고 더 있어야 할 것: 만든 것 모음, 글, 나에 대한 소개.
- 구조: 홈 + 이력서 페이지. `jaywapp.com`은 홈, 이력서는 따로 둔다(예: `jaywapp.com/resume`).
- 홈의 큰 제목은 이름이 아니라 슬로건이다. "타이틀에 이름보단 슬로건이 맞아보여" (2026-11-14). 슬로건은 지금 사이트에 있는 "업무의 마찰을 시스템으로 해결합니다"를 썼고, 이름과 직무는 그 아래 한 줄로 내렸다. 이력서 페이지의 제목은 이름 그대로다.

그래서 이 라운드는 **홈 화면**만 다룬다. 이력서 페이지는 3라운드 시안을 그대로 쓰고, 홈의 "이력서" 링크가 짝이 되는 3라운드 시안으로 간다.

## 요청 분석

| 구분 | 내용 |
|---|---|
| 사용자 작업 | 1. 누구인지 안다. 2. 만든 것을 보고 해당 페이지로 간다. 3. 글을 보고 블로그로 간다. 4. 이력서로 간다. |
| 필수 화면 | 홈 한 페이지: 소개, 만든 것, 글, 이력 요약과 이력서 링크, 연락처 |
| 보존할 의미 | 만든 것마다 무엇인지 한 줄. 글마다 쓴 날짜 |
| 예외·데이터 범위 | 글 제목이 길다. 만든 것이 늘어난다. 글이 오래됐다 |
| 완료 기준 | 세 시안이 PC·모바일, 라이트·다크에서 열리고, 홈에서 이력서 시안으로 넘어간다 |
| 추가 필드 요구 | 소개 문장, 만든 것 목록과 한 줄 설명, 글 목록을 가져올 방법 |

## 시안에 넣은 내용과 출처

- 소개 두 문단: 사이트에 이미 있는 사실로 새로 썼다. 사용자가 확정해야 한다.
- 만든 것 4개: 아이엠 헤드코치(같은 도메인의 `/iam-headcoach/` 소개 문구), Claude Buffett, AI Debate, CardRadar(`src/data/content.ts`).
- 글 5개: 2026-11-14에 블로그 피드에서 읽은 최근 기술 글이다. 가장 최근 글이 2023-03-08이다.
- 이력 요약: 최근 두 회사.

## 시안

### K 한 열 (`concept-01`, 이력서 짝: F 한 열)

좁은 한 열에 차례로 놓는다. 위에 이름과 메뉴 네 개, 그 아래 슬로건·소개·연락처, 만든 것, 글, 이력.

- 장점: 가장 덜어 냈다. 개인 사이트로 가장 익숙한 형태다. 휴대폰과 PC가 같다.
- 단점: 넓은 화면에서 좌우가 빈다. 만든 것이 늘면 길어진다.

### L 라벨 (`concept-02`, 이력서 짝: G 라벨)

모든 부분이 한 줄씩이다. 왼쪽 라벨(소개, 만든 것, 글, 이력, 연락처), 오른쪽 내용. 메뉴는 슬로건 옆 왼쪽 열에 세로로 있다.

- 장점: 무엇이 어디 있는지 라벨만 보면 안다. 항목이 늘어도 구조가 그대로다.
- 단점: 선이 많다. 개성은 가장 약하다.

### M 명함 (`concept-03`, 이력서 짝: I 펼침)

첫 화면은 명함이다. 큰 슬로건, 이름과 직무, 소개, 메뉴 낱말. 그 아래에 만든 것과 글이 두 열로 나란히 있고, 이력 요약이 이어진다.

- 장점: 첫인상이 가장 또렷하다. 만든 것과 글을 한눈에 같이 본다.
- 단점: 첫 화면에 내용이 없다. 글이 오래되면 두 열 중 하나가 허전해진다.

## 같은 기준 비교

| 기준 | K 한 열 | L 라벨 | M 명함 |
|---|---|---|---|
| 첫 화면 | 메뉴, 슬로건, 소개 | 슬로건, 소개, 만든 것 시작 | 슬로건과 소개, 만든 것·글 시작 |
| 만든 것·글 배치 | 위아래 | 라벨 줄 | 좌우 두 열 |
| 메뉴 | 위 가로 줄 | 왼쪽 세로 | 명함 안 낱말 |
| 항목이 늘 때 | 길어짐 | 가장 잘 버팀 | 두 열 길이가 어긋남 |
| 인상 | 조용함 | 단정 | 또렷함 |

## M 확정 뒤 바뀐 것 (2026-11-14)

사용자 결정

- 홈 순서: "사실 만든것보다 내가 회사에서 어떤일을 하는지가 먼저나오면 좋겠어." 명함 → 회사에서 하는 일 → 회사 밖에서 만든 것 → 글 → 이력.
- 만든 것에 넣을 프로젝트 13개를 사용자가 골랐다. 서비스와 앱: 아이엠 헤드코치, 팀프레드, 이지스쿼드, 스뽀쓰-맨, Marvelog, 내새끼달력, 경충FC, CardRadar. 개발자 도구와 AI: cc-jsonl-monitor, key-man, p4-harness, Task Token Meter, AI Debate.
- 고르지 않은 것: WAM, Claude Buffett, toss-readonly-mcp.
- 링크 규칙: "배포까지 한 친구는 완전품 링크 + 공개프로젝트는 github주소 + 비공개프로젝트는 설명만."

M 시안(`concept-03`)에 반영한 것

- "회사에서 하는 일": 현재 회사와 직무 한 문장, 그 아래 분야 네 개(AI·AX, 빌드·배포, 업무 도구, 운영·온보딩)와 분야별 작업 이름. 이력서와 같은 데이터에서 만든다. 분야 분류와 작업의 짧은 이름은 1라운드에서 내가 붙인 것이라 확인이 필요하다.
- "회사 밖에서 만든 것": 두 묶음, 2열 목록. 이름은 완성품이 있으면 완성품으로, 없으면 GitHub로 간다. 아래에 "사이트"·"GitHub" 같은 링크가 따로 있다.
- 소개 둘째 문단을 고른 프로젝트에 맞게 고쳤다(Claude Buffett 언급 삭제).
- 한 줄 설명은 각 프로젝트 README와 스토어 문구에서 가져왔다. 모든 링크가 200으로 열리는 것을 2026-11-14에 확인했다.
- K, L은 고르지 않은 시안이라 순서를 바꾸지 않았다. 프로젝트 목록만 같은 데이터로 바뀌었다.

사용자 추가 결정 (2026-11-14, 두 번째)

- 회사 업무 3건 추가: 작업 관리 솔루션(웹) 개편 및 운영, 대사 작업을 위한 툴 개발, Slack 봇을 통한 알림 체계 확립. 제목만 받았고 상세는 없다. `../career-site/shared/data.js`에 넣어 이력서 시안에도 같이 나온다. 분야는 내가 붙였다(앞의 둘은 업무 도구, 마지막은 운영·온보딩).
- "스마일게이트에서 ~로 일합니다" 문장은 부담스럽다고 해서 뺐다. 홈의 소개와 "회사에서 하는 일" 문장에 회사 이름을 쓰지 않는다.
- 대신 회사 가로 로고를 "회사에서 하는 일" 아래에 붙인다. 공식 로고 파일을 받지 못해 시안에는 점선 자리만 있다. 로고를 직접 그리거나 비공식 파일을 쓰지 않는다.
- 영문 직무 표기(Developer Productivity & Tooling Engineer)는 사용자가 맞는지 물었고 아직 정하지 않았다.

사용자 추가 결정 (2026-11-14, 세 번째)

- 구획 제목은 짝이 맞아야 한다("회사안에서 회사밖에서 / 출근후 퇴근후 이런 라임"). **출근 후 / 퇴근 후**로 바꿨다. 메뉴도 같다. 소개 둘째 문단도 "출근 후에는 ..., 퇴근 후에는 ..."으로 맞췄다.
- 영문 직무: 사용자는 DX(Developer Experience)를 선호하고 게임 개발 업무 환경이 드러나길 원한다. 후보로 `Developer Experience Engineer, Game Development`를 넣어 봤으나, 사용자가 "영문명은 처음에 만들었던 내용으로 되돌려"라고 해서 **`Developer Productivity & Tooling Engineer`로 확정**했다.
- 로고: 사용자가 찾아 달라고 했다. 스마일게이트 공식 사이트(`https://www.smilegate.com/assets/img/common/logo_black.svg`, `logo_white.svg`)에서 2026-11-14에 받은 워드마크를 `shared/smilegate-logo-*.svg`에 두고 고치지 않은 채 쓴다. 상표 사용 허락은 확인하지 못했다.
- "퇴근 후" 첫 문장("내가 쓰고 싶은 서비스와 일할 때 필요한 도구를 직접 만듭니다.")과 "출근 후" 문장의 "게임 개발 조직"은 내가 쓴 문구다. 사용자 확인이 필요하다.

남은 확인

- 스뽀쓰-맨은 경기 예측 사이트다. 이력서와 같은 사이트에 올려도 되는지는 사용자가 골랐으므로 그대로 넣었다.
- 경충FC 사이트는 클럽 구성원용이다. 외부 방문자가 눌렀을 때 무엇이 보이는지 확인하지 않았다.
- key-man의 "다운로드"는 GitHub 릴리스 목록으로 간다. Task Token Meter는 미리보기 릴리스만 있어 GitHub 링크만 뒀다.
## 추천 (선택 전 기록)

**M 명함**을 추천한다. "내 사이트"라는 느낌이 가장 분명하고, 이력서(I 펼침)로 넘어갔을 때 같은 굵은 글자와 선이 이어진다. 조용한 쪽을 원하면 K다.

## 확인한 것

- 세 시안 × 1440·390·320px × 라이트·다크: 가로 넘침 0, 페이지 오류 0.
- M에서 "이력서 전체 보기"를 누르면 I 펼침으로 넘어간다.

## 확인하지 못한 것

- 스크린 리더, 실기기, 200% 확대.
- 이력서 시안에는 아직 홈으로 돌아가는 링크가 없다. 고른 뒤 구현할 때 넣는다.

## 미결정 사항

1. 홈 시안 선택과 이력서 시안 선택(3라운드 F~J).
2. 글: 가장 최근 글이 2023년 3월이다. 홈에 글 목록을 보일지, 블로그 링크만 둘지. 목록을 보이면 빌드할 때 피드를 읽어 갱신하는 방식이 필요하다.
3. 만든 것에 더 넣을 항목. 공개 레포가 더 있지만 설명을 지어내지 않으려고 네 개만 넣었다.
4. 소개 문장 확정.
5. 이력서 주소(`/resume` 등)와 기존 `/ko/`, `/en/` 주소 처리.
