## 공통 규칙

- 내용은 `src/data/content.ts`와 `messages/ko.json`에서 그대로 옮겼다(`shared/data.js`). 경력·수치를 새로 만들지 않았다.
- 기존 문구 가운데 줄표(em-dash)와 이모지는 뺐다. 그 밖의 문장은 다듬지 않았다.
- 세 시안 모두 한국어만 만들었다. 영어는 고른 시안을 구현할 때 넣는다.
- GitHub 활동 그래프는 세 시안 모두 뺐다. 이력서로 읽히는 데 도움이 적다고 봤다. 필요하면 되살린다.
- 글꼴: Pretendard 1.3.9(jsDelivr). 아이콘: Phosphor 2.1.1(unpkg). 시안 01만 숫자·부품 번호에 JetBrains Mono(Google Fonts)를 쓴다.
- 라이트·다크는 시스템 설정을 따른다. `prefers-reduced-motion`과 검토 도구의 "정지"에서 모든 모션이 꺼진다.

## 시안

### 01 기판

경력 전체를 회로 기판 한 장으로 그린다. 시간은 구리 배선, 회사는 배선 위의 부품, 작업은 부품의 핀이다. 펜타큐브에서 6년간 PCB 설계 검증 도구를 만든 이력에서 가져온 형식이다.

- 첫 화면: 왼쪽에 문장과 버튼, 바로 아래에 2015년부터 현재까지 이어지는 기판. 최근 작업 하나가 미리 골라져 있다.
- 탐색: 핀을 고르면 기판 아래 검사 칸에 작업 내용이 나온다. 분야 버튼으로 해당 핀만 남긴다. 고른 핀은 주소에 남는다.
- 기판 아래에 같은 내용을 글로 읽는 "경력과 작업 전체"가 있다. 사양 표에 기술·학력·자격을 모았다.
- 모바일: 기판을 빼고, 세로 배선 옆에 회사와 작업을 최근 순으로 읽는다.
- 모션: 처음 열 때 배선이 2015년에서 현재까지 한 번 그어진다. 경력이 이어져 왔음을 보여 준다.
- 장점: 한눈에 기억에 남는다. 재직 기간의 길이와 작업 수가 그림으로 보인다. 이력과 형식이 맞닿아 있다.
- 단점: 핀 이름이 기울어 있어 훑어 읽기는 느리다. 기판을 모르는 사람에게는 설명 한 줄이 필요하다. 모바일에서는 그림이 사라진다.
- 구현 부담: 높음. SVG 좌표 계산과 영어 라벨 길이 대응이 필요하다.

### 02 문서

사이트 자체가 이력서다. 위에서 아래로 한 번 읽으면 끝나고, 그대로 A4로 인쇄된다.

- 첫 화면: 이름을 가장 크게, 그 아래 직무. 왼쪽 여백 열에 연락처·기술·학력·자격, 오른쪽에 소개 문장과 첫 회사.
- 탐색: 스크롤뿐이다. 작업이 많은 회사는 5개만 보이고 나머지는 "작업 9개 더 보기"로 편다.
- "PDF로 저장" 버튼이 인쇄 창을 연다. 인쇄할 때는 접힌 작업이 모두 펴진다.
- 모바일: 이름, 소개, 연락처·기술, 경력 순서.
- 모션: 없다.
- 장점: 채용 담당자가 가장 빨리 읽는다. 인쇄·PDF가 된다. 구현과 유지가 쉽다.
- 단점: 가장 평범하다. 사람의 개성이나 일하는 방식이 형식에서 드러나지 않는다.
- 구현 부담: 낮음.

### 03 색인

경력을 날짜가 아니라 푼 문제의 종류로 나눈다. 공구 노랑 패널에 분야 다섯 개가 있고, 하나를 고르면 회사를 가리지 않고 그 분야의 작업이 옆에 놓인다.

- 첫 화면: 왼쪽 노랑 패널에 문장과 분야 목록(작업 수 포함). 오른쪽에 소개 한 문단, 경력 4줄 표, 첫 분야의 작업.
- 탐색: 분야를 고르면 오른쪽 작업 목록이 바뀐다. 고른 분야는 주소에 남고 뒤로 가기가 된다.
- 모바일: 노랑 패널이 위로 가고, 분야 목록은 화면 위에 붙는 가로 줄이 된다.
- 모션: 분야를 바꾸면 작업이 위에서부터 차례로 놓인다. 목록이 바뀌었음을 알린다.
- 장점: "무슨 일을 하는 사람인가"가 가장 분명하다. 경력 표가 첫 화면에 있어 이력서 역할도 한다. 인상이 강하다.
- 단점: 분야 분류가 내 판단이라 사용자가 고쳐야 할 수 있다. 노랑이 강해 취향을 탄다. 인쇄에는 맞지 않는다.
- 구현 부담: 중간. 작업마다 분야 값을 데이터에 추가해야 한다.

## 추천

**03 색인**을 추천한다. 두 독자를 비슷하게 본다는 답에 가장 맞다. 첫 화면 오른쪽의 경력 표가 이력서 역할을 하고, 분야 목록이 "어떤 문제를 푸는 사람인가"를 보여 준다. 인쇄용 이력서가 필요하면 02의 인쇄 화면을 03에 "PDF로 저장" 경로로 붙일 수 있다.

기억에 남는 것을 가장 앞세운다면 01이다. 빠르고 안전한 것을 원하면 02다.

## 미결정 사항

1. 시안 선택.
2. 작업의 분야 분류(`shared/data.js`의 `theme`)가 맞는지. 특히 "업무 도구"와 "운영·온보딩"의 경계.
3. 소개에 쓰는 수치. 현재 문구는 "9년 넘게"인데 `messages`에는 "총 경력 9년 4개월"도 있다. 어느 표현을 쓸지.
4. GitHub 활동 그래프를 되살릴지.
